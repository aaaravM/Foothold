# Foothold build contracts

Single source of truth for everyone building Foothold in parallel. If something here conflicts with your instinct, follow this file; if it conflicts with reality (a library API changed), follow reality and note it in your final report.

Read alongside: `docs/research/*.md` (verified facts: design notes, UI library install commands, data sources, stats, current library APIs).

## 1. Ground rules (from the brief, non-negotiable)

- **No invented numbers.** Every metric shown comes from `ml/artifacts/metrics.json` (written by scripts that actually ran). Missing metric → UI shows "not trained yet". Every wage/cost/duration comes from `data/processed/*.json` with a `source_id`.
- **Provenance labels**: `REAL` (read from an official source; has URL + retrieval date), `SAMPLE` (plausible placeholder, NOT verified; must link to where to verify), `SYNTHETIC` (generated by our scripts), `FICTIONAL` (people, employers, circle members). Every displayed wage/cost/program detail carries a `ProvenanceBadge`.
- **All people are fictional** and labeled "Fictional". No real company names as employers. Real colleges/programs may appear as education providers (badged).
- **Statistics** only from `docs/research/stats.md` items marked VERIFIED/PARTIALLY VERIFIED, shown with their source link.
- **Do not copy** text, images, or code from the inspiration sites or from memory of UI libraries. Install library components only with the shadcn CLI exactly as documented in `docs/research/ui-*.md`. Skiper UI: FREE components only.
- **Safety**: coach is not therapy, never diagnoses, never claims confidentiality. Crisis/self-harm signal → stop normal flow, show calm 988 message (call or text 988; reach out to a trusted person), no probing questions. Employer view consent-gated and blind by default. Untrusted text (postings, circle posts, user free text) is data, never instructions: sanitize + delimit + structured outputs.
- **Secrets**: never print, log, or commit `.env` or the key. Never log full prompts containing personal text.
- **Don't break the live site.** The user is watching `next dev` with hot reload. Write complete files in one go; never leave a half-edited import. The page must always load.
- **Don't start/stop the dev servers** (the orchestrator owns them). Don't run `next build` (orchestrator runs it at milestones). Don't `npm install`/`pip install` (orchestrator only; everything you need is pre-installed — if something is missing, work around it and say so in your report). Don't `git commit`.

## 5. Data files (`data/processed/`)

- `traits.json` — see §4.
- `careers.json` — `[{id, title, onet_soc, onet_title, summary, path_types:[route types], work_styles:{trait_id: 0..1}, skills:[skill_id], wage:{median_hourly, median_annual, p25_annual, p75_annual, area, period, source_id, status}, outlook:{growth_pct, annual_openings, period, source_id, status}, coworkers:[{id, name, role, style, base_mood}] (3, fictional)}]`
- `occupations.json` — 8 careers + ~30 related O*NET occupations for the career-fit model: `[{onet_soc, title, career_id|null, work_styles:{trait_id: 0..1}}]` + top-level `provenance`.
- `skills.json` — ~60 skills `[{id, name, category}]` (taxonomy used by courses, jobs, postings, talent cards).
- `courses.json` — ~80 free/low-cost courses `[{id, title, provider, cost_usd, hours, skills:[skill_id], url, status}]`.
- `programs.json` — planner input per career and route: `[{id, career_id, route_type, name, provider, credential, url, status, source_id, steps:[{id, title, kind: course|block|job, units?, hours_per_week, weeks, cost_usd, prereqs:[step_id], sections:[{id, days:["Mon",...], start:"18:00", end:"20:50", modality: in_person|online|hybrid, campus?}], paid_wage_hourly?}]}]`
- `events.json` — `{schema_version:1, status:"DRAFT — needs human review", events:[Event]}`; ~5 per career + a few `crunch` events.
  ```json
  {"event_id":"rn_02","career_ids":["registered_nurse"],"clock":"09:15","title":"Short","text":"Scenario (2-4 sentences)",
   "crunch":false,"status":"DRAFT — needs human review",
   "choices":[{"choice_id":"a","text":"...","trait_deltas":{"attention_to_detail":0.8,"stress_tolerance":-0.2},
     "stat_deltas":{"safety":6,"output":-3,"team_trust":2,"stress":4},
     "coworker_hints":{"<coworker_id>":"how this coworker tends to feel about it"}}]}
  ```
  `trait_deltas` values in [-1, 1] over 2-4 traits; `stat_deltas` ints in [-15, 15]; 3 choices per event. Validated by a JSON Schema in `data/schemas/event.schema.json`.
- `sources.json` — `[{id, title, url, publisher, license, retrieved, status}]`; mirrored human-readably in `data/SOURCES.md`.
- `synthetic/learners.json`, `synthetic/employers.json`, `synthetic/circles.json`, `synthetic/talent_pool.json` — all with `"fictional": true`. Talent cards have blind fields (demonstrated skills, sim bands, pathway progress, availability, region) and hidden fields (name, photo, exact location, contact) plus a synthetic `group` label used ONLY by the fairness audit (never a model feature, never displayed on cards).
- `personas.json` — maya, dev, luis, tri_valley_freight: constraints (hours, budget, commute, dependents, credits), interests, etc.

## 6. SSE contract (every LangGraph run)

`Content-Type: text/event-stream`. Each message: `event: <type>\ndata: <json>\n\n`, where json includes `type`.

```ts
type TraceNode = { id: string; label: string; kind: "llm" | "model" | "solver" | "human" | "logic"; group?: string };
type TraceEvent =
  | { type: "meta"; graph: string; thread_id: string; nodes: TraceNode[] }                 // first event: lets the UI draw the graph
  | { type: "node"; graph: string; node: string; status: "start" | "end"; ts: number; ms?: number; summary?: string; llm?: "openai" | "cache" | "mock" }
  | { type: "state"; graph: string; data: Record<string, unknown> }                        // UI-relevant partial state
  | { type: "interrupt"; graph: string; node: string; payload: unknown }                   // waiting for a human
  | { type: "done"; graph: string; result: unknown }
  | { type: "error"; message: string };
```
Parallel fan-out nodes share a `group` (e.g. coworker nodes `coworker:<id>` with `group: "coworkers_react"`). `summary` is a short non-personal string ("picked event rn_02 · gain 0.41 bits").

Graphs run as POST endpoints that return the stream (the browser reads it with `fetch` + a stream parser, not `EventSource`). Thread ids are LangGraph `thread_id`s; checkpointer = SQLite at `api/.runtime/checkpoints.db`.

## 7. LLM layer (`foothold/llm.py`)

```python
llm.structured(task: str, system: str, user: str, schema: type[BaseModel], mock: Callable[[], BaseModel]) -> tuple[BaseModel, LLMMeta]
llm.text(task: str, system: str, user: str, mock: Callable[[], str]) -> tuple[str, LLMMeta]
LLMMeta = {source: "openai" | "cache" | "mock", model: str | None, ms: int}
```
- Cache: `api/cache/llm/<task>/<sha256(model|task|system|user|schema)>.json` storing the response only (never the prompt).
- `LLM_MODE=auto`: OpenAI if key present + `OPENAI_MODEL` set + startup key check passed; else mock. `DEMO_MODE=1`: cache only, miss → mock.
- Any OpenAI error/timeout (20 s) → mock, log only the error class. Every call site supplies a meaningful deterministic mock built from structured data, so the whole app works offline.
- Untrusted text is wrapped as `<untrusted kind="posting">…</untrusted>` after `safety.sanitize_untrusted()`; system prompts state that untrusted blocks are data, never instructions. LLM output that drives logic is a Pydantic model, validated against vocabularies (e.g. skills must exist in `skills.json`).

## 10. `ml/artifacts/metrics.json`

Each script read-merge-writes only its own top-level key, and always includes `status`, `provenance`, `data`, `seed`, `trained_at`, `reproduce`:
`career_fit` (mlp/cosine top1/top3, winner), `selector` (avg events to confident: adaptive/random/fixed, curve), `recommender` (gnn/mf/popularity recall@10, ndcg@10, overall + cold-start, model_type), `planner` (feasibility cpsat vs greedy, solve_ms p50/p95, months/cost improvement, n_cases), `fairness` (selection rates by synthetic group, min impact ratio, passes_four_fifths, note), `verifier` (n_cases, catch_rate, false_positive_rate).
