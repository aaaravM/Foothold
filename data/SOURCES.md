# Foothold data sources

Generated by `data/build_sources.py` from `data/processed/sources/*.json` (one file per producer). Do not edit by hand: change the producer file and re-run.

```bash
$FOOTHOLD_PY data/build_processed.py      # O*NET backbone, skills, courses, jobs (add --verify-courses to re-check pages)
$FOOTHOLD_PY data/build_sources.py        # this file + data/processed/sources.json
$FOOTHOLD_PY data/validate.py             # check every processed file
```

## Provenance labels

- **REAL**: read from an official source on the retrieval date (URL and date given).
- **SAMPLE**: plausible placeholder, NOT verified; check the linked page before treating it as fact.
- **SYNTHETIC**: generated by Foothold scripts.
- **FICTIONAL**: invented people, employers, and communities.

Every displayed wage, cost, duration, or program detail carries one of these labels and a `source_id` that points to a record below.

Foothold modified this data. Changes:

- Work Styles WI values (-3..+3) converted to 0..1 percentile ranks across all occupations with complete Work Styles data (traits.json ids, occupations.json, careers.json).
- Element names mapped to snake_case ids; Work Styles and skill descriptions copied verbatim from content_model_reference.csv.
- Career skill lists choose the 5 O*NET skills with the highest Importance relative to the all-occupation mean, combined with Foothold job-specific skills.
- Only 42 of the 1,016 occupations are kept in occupations.json (8 Foothold careers + 34 related occupations).
- Foothold career titles and summaries are Foothold's own; O*NET titles are kept in onet_title.

## Methods

### Work styles (traits) on a 0..1 scale

For each of the 21 O*NET 31.0 Work Styles and each occupation: value = (number of occupations with a lower Work Styles Impact (WI) + 0.5 x number with the same WI) / 891, where 891 is every O*NET-SOC occupation with complete Work Styles data (21 elements, WI and DR). 0.5 is about the middle of all occupations; 0.9 means a higher WI than about 90% of occupations. Raw WI and DR stay in occupations.json. (source: `onet_31_0`)

### Career skills

careers.json skills = Foothold job-specific skills (editorial, SAMPLE) + the 5 O*NET 31.0 skills with the highest Importance z-score versus the mean of all 910 occupations with Skills data, among skills with Importance >= 2.5. (source: `onet_31_0`)

## Adding a source

1. Write `data/processed/sources/<producer>.json`: a JSON list of records (or `{"sources": [...]}`). Required fields: `id` (snake_case, unique across producers), `title`, `url`, `publisher`, `license`, `retrieved` (YYYY-MM-DD, or null for Foothold-made data), `status` (REAL, SAMPLE, SYNTHETIC or FICTIONAL). Optional: `attribution` (credit line shown verbatim), `license_url`, `modified`, `modifications`, `methods`, `notes`, `files`, `providers`, `used_by`.
2. Point each processed record at it with `source_id` (and give it a `status`).
3. Re-run `data/build_sources.py`, then `data/validate.py`. On an id clash the first producer file in alphabetical order wins and the clash is listed under Merge warnings.
